## 维护约定（2026-10-14 归纳，避免重复踩坑）

### 1. 订阅文件
- `全部.json` —— 影视综合订阅，顶层 `name` 固定为「全部」。
- `部分.json` —— 成人向订阅（`_adult:true`），顶层 `name` 固定为「部分」。
- 两个文件顶层 `name` **不要改**，count 字段在清理后自动同步。

### 2. 每日流水线自动清理（pipeline.yml）
- `discover` → `build`(ysc_build) → `classify`(qwjs_classify) → `output`(cs_build) →
  **`cleanup`(cleanup.py，2026-10-14 新增)** → `probe`(probe.py) → `recheck`(probe --recheck)。
- **probe.py**：死链检测 + 精确 api 去重 + 防抖暂留；引擎源/连续失效源直接丢弃。
- **cleanup.py（新增）**：在 probe 之前做语义级清理，对 `全部.json` 与 `部分.json` 同时生效：
  1. **删纯音频源**：音乐 / 听歌 / 听书 / 有声 / 广播 / 电台 / KTV / 相声 / 评书 / radio / 网易云 /
     千千音乐 / 枫叶音乐 / 悦听 / 音乐聚合 / DJ / 听小说 / 漫画 / 绘本 / 书城 / 电子书 等。
     视频类（直播 / 戏曲 / 电视 / 体育 / 虎牙 / 哔哩 / 动漫 / 短剧 等）一律保留；视频关键词优先级高于
     音频，防误删。
  2. **删「藤藤 / 谐音」源**：藤、腾、滕、疼、填、瑅 任一命中即删（均为依赖第三方解析、易失效的
     爬虫源，用户实测不可用）。
  3. **删成人内容（仅 `全部.json`）**：用户点名（鲨鱼 / 瘙女 / 樱花 / 百花 / 幸福 / 私人资源 /
     国产资源 / 剧屋 / isese）+ 强色情关键词（无码 / 麻豆 / 探花 / 换妻 / 群p / 乱伦 / 人妻熟女 /
     萝莉少女 / 巨乳美乳 / 强奸 / 迷奸 / 调教 / 中出 / 潮吹 / 制服诱惑 / 强制侵犯 / 海角社区 等）。
     ★ **刻意排除「写真 / 人妻 / 熟女 / 少妇 / 丝袜」作「分类级」判定**——它们常出现在普通电影站的
     `categories` 分类里（如闪电资源 / 最大资源 / 猫眼资源都含「写真」），只作「源名级」判定，避免误删。
     `部分.json` 是成人向订阅，跳过此步、保留成人内容。
  4. **同站 / 同规则 去重**：
     - type 0/1：按资源站品牌归并（剥 api./cj. 前缀、合并同站别名域名，如 lziapi/lzizy/lzzy → 量子），
       同站只留 1 个最优。`zhangqun` 同服务器多应用组整体保留。
     - type 3（drpy 爬虫源）：按「规则文件」归并（ext 非空取 ext，否则取 api），同规则只留 1 个。
       ★ **排除空 ext 的源**（467 个空 ext 源各指向不同 api 规则文件，不能当重复删，否则误删几百个）。
  5. 名字保持「全部」/「部分」不变，同步 count；脚本幂等可重复跑。
- 规则来源：藤藤（解析链死源）、非凡/量子/360 等（同站重复）、音乐/听书（非影视）、鲨鱼/樱花等
  （成人）、写真分类误报（普通电影站分类）均为人工排查后固化。

### 3. 对外链接约定（交付时务必遵守）
- **链接必须用字面中文路径**：`main/全部.json`，**不要 URL 编码**（`%E5%85%A8...` 影视仓识别不出）。
- **镜像优先用 gh-proxy.com 实时代理**（每次从 GitHub 拉最新）：
  `https://gh-proxy.com/https://raw.githubusercontent.com/dearloyal/CS/main/全部.json`
  —— **不要用 jsDelivr**（cdn.jsdelivr.net 会缓存旧内容，实测返回清理前的旧 840 源）。
- 直连 `https://raw.githubusercontent.com/dearloyal/CS/main/全部.json` 作慢速备用。
- 交付链接时**每条单独成块、可单独长按复制**；非用户要求**不发产物 / 文件预览**。
